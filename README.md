# Huawei Return Management System

ระบบจัดการรับคืนสินค้า Huawei Marketplace (TikTok / Shopee / Lazada / HUAWEI Web) ของ SYNNEX
เว็บแอปไฟล์เดียว (`index.html`) ไม่ต้อง build ใช้ Firebase Firestore เป็นฐานข้อมูลกลาง ใช้ได้ทั้งคอมพิวเตอร์และมือถือ

## ฟีเจอร์
**งานประจำวัน**
- **Workflow 10 ขั้น**: สร้างคำขอคืน → รอรับสินค้า → ได้รับสินค้าแล้ว → รอทดสอบ → กำลังทดสอบ → ทดสอบเสร็จ →
  เคลม Platform / ส่งคืนลูกค้า → รอทำรับคืน (CN) → ปิดงาน — ปุ่ม "ถัดไป" เสนอเฉพาะขั้นที่ถูกต้องตามผลทดสอบ
- **ถาม-ตอบในเคส** ระหว่างฝ่ายขาย / คลัง / IPQC / ผู้ดูแล + เมนู **กล่องข้อความ** (ถึงฉัน / รอตอบ) + แจ้งเตือนเมื่อมีข้อความใหม่
- **สแกนก่อน (Scan-first)**: ช่องสแกนบาร์โค้ด Invoice / PA / RO / Tracking เปิดเคสทันที พร้อมแผงตรวจรับเทียบ Serial
- **อัปเดตหลายเคสพร้อมกัน** (รับของทั้งคันรถ / ปิดงานทีละชุด), ค้นหาทุกเลขเอกสาร, ตัวกรองช่วงวันที่, แบ่งหน้า
- **ฟอร์มเคส**: บันทึกเฉพาะช่องที่เปลี่ยน (ข้อมูลเดิมไม่หาย) + ประวัติก่อน/หลัง, กันกดซ้ำ, เตือนเลขซ้ำ, บีบอัดรูป,
  ลายเซ็นรับ/ส่งแยกพร้อมชื่อและเวลา, ช่อง CN / RO / ขนส่งส่งคืน / Claim / กล่องที่ / การส่งมอบ
- ตั๋วรับคืนพร้อมบาร์โค้ด (พิมพ์ หรือดาวน์โหลดเป็น HTML), Export Excel ตามที่กรองบนจอ

**ข้อมูลและความถูกต้อง**
- ซิงก์ **real-time ทุกเครื่อง** + ทำงานต่อได้เมื่อสัญญาณหลุด (แคชออฟไลน์) พร้อมป้ายสถานะการซิงก์
- ลบแบบย้ายไป **ถังขยะ** กู้คืนได้, **สำรองข้อมูล (JSON)** และกู้คืนสำหรับผู้ดูแล
- **นำเข้า Excel / JSON แบบ preview → ยืนยัน**: รวมกับเคสเดิม (ไม่สร้างซ้ำ), รายงานผลตามจริง, ผู้ดูแลยกเลิกชุดที่นำเข้าได้

**ผู้ใช้และสิทธิ์**
- **สมัครด้วยอีเมลอะไรก็ได้** (Gmail / Hotmail / อีเมลบริษัท) + รหัสผ่าน ไม่ต้องตั้งค่าใน Firebase เพิ่ม
- บัญชีกลางใช้ได้ทุกเครื่อง: สมัครในหน้าเว็บ → **ผู้ดูแลอนุมัติ** (สมัครเป็นผู้ดูแลเองไม่ได้), ระงับ/เปลี่ยนสิทธิ์มีผลทันที
- ลืมรหัสผ่าน: ผู้ดูแลกด **รีเซ็ตรหัสผ่าน** ในเมนูจัดการผู้ใช้ (ระบบไม่ส่งอีเมล จึงไม่ต้องตั้งค่าเซิร์ฟเวอร์อีเมล)
- รหัสผ่านเข้ารหัส PBKDF2 + salt, เซสชันหมดอายุ 12 ชม., ไม่ใช้งาน 30 นาทีออกอัตโนมัติ
- 4 บทบาท: ผู้ดูแล / ฝ่ายขาย ECOM / คลังสินค้า / IPQC-Service

**สำหรับหัวหน้างาน**
- Dashboard: เคสเปิด / ใหม่วันนี้ / รับวันนี้ / ปิดวันนี้, อายุงานค้าง, รายการไม่เคลื่อนไหว, กราฟ 7 วัน, Trendline

## ติดตั้งบน GitHub Pages
1. สร้าง repository แล้วอัปโหลด `index.html`, `README.md`, `firestore.rules`, `.gitignore` (และโฟลเดอร์ `tools/` ถ้าต้องการ)
2. Settings → Pages → Source: branch `main` / root → Save
3. เปิด `https://<username>.github.io/<repo>/`

## เริ่มใช้งานครั้งแรก
1. เปิดเว็บ → **สมัครสมาชิก** ด้วยอีเมลของคุณ → บัญชีแรกของระบบเป็น **ผู้ดูแล (Admin)** อัตโนมัติ
2. พนักงานสมัครเองด้วยอีเมล → ผู้ดูแลเข้า **จัดการผู้ใช้** กด **อนุมัติ** และเลือกบทบาท
   (ระบบไม่ได้ส่งอีเมลยืนยัน — ผู้ดูแลควรตรวจว่าเป็นพนักงานจริงก่อนกดอนุมัติ)
3. บัญชีระบบเก่า (เก็บแยกต่อเครื่อง) ใช้ไม่ได้แล้ว ทุกคนสมัครใหม่ครั้งเดียว

## นำเข้าข้อมูลเก่าจาก Excel (ครั้งเดียว)
ไฟล์ `reconciled_cases.json` (7,009 เคส) สร้างจากไฟล์ Excel เดิมด้วย `tools/reconcile.ps1` แล้ว
— ซ่อมคอลัมน์เยื้อง, รวมเคสซ้ำข้าม sheet โดยเก็บสถานะที่ก้าวหน้าที่สุด, แก้วันที่สลับวัน/เดือน, แยกเลข CN / RO / ผล Claim
1. เข้าระบบเป็นผู้ดูแล → **นำเข้า Excel** → เลือก `reconciled_cases.json`
2. ตรวจหน้า **preview** (จำนวนเคสใหม่ / อัปเดต / ซ้ำ) → กด **ยืนยัน**
3. นำเข้าซ้ำได้อย่างปลอดภัย ระบบจะไม่สร้างเคสซ้ำ
4. **อย่าอัปโหลดไฟล์ JSON / Excel ขึ้น GitHub** เพราะมีข้อมูลลูกค้า

## ตั้งค่า Firebase (แนะนำ)
- Firestore → Rules: วางเนื้อหา `firestore.rules` → Publish (ห้ามลบถาวร, ตรวจรูปแบบข้อมูล, ปิด collection อื่น)
- เปิด Point-in-time recovery / Scheduled export (แผน Blaze) หรือให้ผู้ดูแลกด **สำรองข้อมูล (JSON)** ทุกสัปดาห์
- **ข้อจำกัดที่ยอมรับ**: ระบบ login อยู่ในหน้าเว็บ (ไม่ใช้ Firebase Authentication) ฐานข้อมูลจึงแยกสิทธิ์ฝั่งเซิร์ฟเวอร์ไม่ได้
  รายละเอียดอยู่ในหัวไฟล์ `firestore.rules` — ถ้าต้องการความปลอดภัยระดับสูง ให้ย้ายไปใช้ Firebase Authentication
